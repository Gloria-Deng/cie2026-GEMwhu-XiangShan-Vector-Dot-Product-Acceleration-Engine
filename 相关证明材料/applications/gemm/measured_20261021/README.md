# 2026-10-21 vdot 完整 GEMM 集成 A/B（16³ / 32³ 真实香山周期窗口）

本包是 `results/gemm/cycles_20261020/` 的追加 A/B，不替换 6.1 的旧读数，也不删除旧包的任何文件。目标是把“每个 8 元素块 `vs1r.v` 存栈、`lw` 取回、再加到标量累加器”这一首要嫌疑拆成可单独归因的实验，而不是把嫌疑直接写成结论。

- 16³：作业 `3732028`，`COMPLETED`，退出码 `0:0`，`02:15:44`，节点 `n0369`；每臂 3 次成功。
- 32³：作业 `3736507`，`COMPLETED`，退出码 `0:0`，`06:47:21`，节点 `n0375`；每臂 1 次成功。
- 同一颗 `run_20261016_m` emu + NEMU DiffTest；同一份 A/B/REF 数据；同一 xpack RISC-V GCC 14.2.0；同一 `-O2 -fno-tree-vectorize -fno-unroll-loops -mcmodel=medany`；同一 `link_landing.ld`/`landing.S`；同一 1024 周期 grid。
- 16³ 的 5 个旧基线在 ±1,024 周期内复现：`6,144 / 6,144 / 5,120 / 33,792 / 29,696`。32³ 的 5 个旧基线逐值复现：`55,296 / 49,152 / 41,984 / 268,288 / 237,568`。见 `baseline_reproduction.csv`。

## 测量口径

guest 在 `pack`（仅 packed）和 `kernel()` 前后读 `cycle` CSR，`delta = t1 - t0`，用 `LANDING_BASE + ((delta >> 10) << 2)` 编入终止 PC；emulator 的 terminal PC 解出 1024 周期分辨率的窗口。

- 包含：A/B 装载、B 打包（packed）、循环控制、MAC/规约、C 写回。
- 不包含：程序启动、镜像加载、结果校验循环、landing 自旋。
- 每个 PASS 都要求 guest 逐元素校验 `mismatches=0` 后才跳 landing；`-C` 不足的尝试作为 FAIL 行保留（16³ 有 2 条：旧 vdot 和旧 vdot_packed 的 20k 首次尝试；32³ 有 5 条：旧 vdot 和旧 vdot_packed 的 100k/200k 两次，以及旧集成 `vdot_unroll4` 的 100k 一次），不删除。
- min/median/max 只统计成功重复；16³ 每臂 3 次，全部三次读数相同；32³ 每臂 1 次。

## 什么改动带来了收益

1. **只换取回方式（vdot_movx）就拿到最大单项收益，而且在两个尺寸上同样成立。** 16³ 从 33,792 降到 5,120（6.60×），32³ 从 268,288 降到 40,960（6.55×）；两个尺寸都低于同布局向量（16³ 6,144→1.20×，32³ 49,152→1.20×）。两次运行的 vdot 数、A/B 装载、K 循环和标量累加完全相同，唯一变化是把每个 8 元素块的 `vs1r.v`+`lw` 换成 `vsetivli e32`+`vmv.x.s`。取回路径的净差在两个尺寸上一致：16³ `33,792−5,120=28,672` 除以 512 个 8 元素块 ≈ **56.0 周期/块**；32³ `268,288−40,960=227,328` 除以 4,096 块 ≈ **55.5 周期/块**。A/B 只能把差值归到“取回路径”，不能再把约 56 周期进一步拆成 store/load 与 vmv 各占多少；这需要单指令成本的 RTL/性能计数器实验。
2. **把结果留在向量寄存器并用 e32 `vadd.vv` 累加（vdot_vecacc）在两个尺寸都没有超过 movx。** 16³ 是 6,144，32³ 是 49,152，两次都**在当前 1024 周期分辨率下与现有向量读数相同**（6,144/49,152），但分别比 movx 慢 1,024/8,192 周期。16³ 每输出只有 2 个 8 元素块，32³ 有 4 块；额外的 `vsetivli e32` + `vadd.vv` 树在两个尺寸上都没有把 `vmv.x.s` 的取回成本赚回来。K 从 16 增到 32 没有改变这个结论。
3. **j 方向展开 4 列（vdot_unroll4）有收益但不够。** 16³ 从 33,792 降到 11,264（3.00×），32³ 从 268,288 降到 94,208（2.85×）；A 装载被 4 列共享、4 条独立 vdot/标量链暴露了 ILP。但它仍保留 `vs1r.v`+`lw`，所以 16³/32³ 分别比现有向量慢 1.83×/1.92×，比 movx 慢 2.20×/2.30×。ILP 不能替代取回方式的改变。32³ 的 100k `-C` 不足被保留，200k 才到 landing。
4. **组合（vdot_vecacc_unroll）的排序依赖尺寸和布局。** 16³ 非打包在当前分辨率下与 movx 读数相同（5,120），打包最好（3,072）；32³ 非打包 46,080，比现有向量 49,152 低 3 个网格步（1.07×），但比 movx 的 40,960 慢 5,120 周期；32³ 打包 22,528，是全部 32³ 臂的最好值，比打包向量 41,984 快 1.86×、比旧 vdot_packed 237,568 快 10.55×。4 列共享 A、vdot 进 v4..v7、e32 `vadd.vv` 累加到 v20..v23、每列只 `vmv.x.s` 一次；打包后 B 连续，收益最大。

**没有收益的路径（两个尺寸）：** vdot_vecacc 单独使用时不如 movx（16³ 6,144 vs 5,120；32³ 49,152 vs 40,960）；vdot_unroll4 的 ILP 收益不足以抵消 `vs1r.v`/`lw`（16³/32³ 都比向量慢 1.8×/1.9×）；32³ 非打包的 vdot_vecacc_unroll 也比 movx 慢 5,120 周期。这些结论都有二进制层面的旋钮落地证据（见下），不是“旋钮没落进汇编”。

**关于相同读数：** `vdot_vecacc` 与现有向量在 16³ 同为 6,144、在 32³ 同为 49,152；`vdot_movx` 与 `vdot_vecacc_unroll` 在 16³ 同为 5,120；打包 16³ 的 `vdot_vecacc` 与 movx 也同为 4,096。预检显示这些臂的 vdot/vadd/vmv/vs1r 计数各不相同且都符合预期，所以相同读数并非实现选项未生效；它只是这个形状、这个窗口和这两个实现下的量化读数相同，无法据此确定真实周期精确相等。不能把相同读数写成“两条路径等价”或外推到 64³。32³ 的 movx（40,960）与 vdot_vecacc_unroll（46,080）读数不同，movx 更快；打包 32³ 的 vdot_vecacc_unroll（22,528）又明显低于 movx_packed（31,744）。

## 旋钮落地审计

`cluster/check_gemm_variants.py` 在实测前对每个 ELF 反汇编，统计 vdot 目标寄存器、`vmv.x.s`、`vadd.vv`、`vs1r.v` 的静态出现次数；`variant_preflight.csv` 是原始输出，20 个 vdot 臂全部 `OK`。要点：

| 臂 | vdot 目标 | `vs1r.v` | `vmv.x.s` | `vadd.vv` |
|---|---|---:|---:|---:|
| 旧 vdot | v26 ×2 | 2 | 0 | 0 |
| vdot_movx | v26 ×2 | 0 | 2 | 0 |
| vdot_vecacc | v4,v5 | 0 | 1 | 2 |
| vdot_unroll4 | v26..v29 | 4 | 0 | 0 |
| vdot_vecacc_unroll | v4..v7 | 0 | 4 | 4 |

所以 movx 与 vecacc 的差异不是“少了一条指令没生成”，而是取回/累加策略本身的周期差；unroll4 确实保留了 4 条 `vs1r.v`。

## 为什么

- 旧 vdot 的每块 `vs1r.v` 写 16 字节栈槽、紧接着 `lw` 读回 4 字节，形成向量存储→标量装载的往返依赖；在香山 emu 的存储层次上，这个往返的成本远高于 `vmv.x.s`。movx 的 A/B 把这部分单独量化出来：16³ 约 56.0 周期/块，32³ 约 55.5 周期/块，说明它是与 K 无关的固定取回成本，而不是算术吞吐问题。
- `vdot_vecacc` 的 e32 `vadd.vv` 需要把 vtype 从 e8 切到 e32 再切回；16³ 的 2 个块和 32³ 的 4 个块都没有把它摊薄，两个尺寸在当前分辨率下与向量读数 6,144/49,152 相同。`vmv.x.s` 每块取回一次仍然更便宜。
- `vdot_unroll4` 的 4 列共享 A 装载减少了 A 的 `vle8.v` 次数，但 4 列仍各有一条 `vs1r.v`+`lw`；所以它比旧 vdot 快约 2.85–3.00×，却仍慢于向量和去掉取回的 movx。
- 32³ 把组合臂的尺寸依赖暴露出来：4 列 × 4 个 8 元素块时，每块一次 e32 `vset` + 4 条 `vadd.vv` 的链比 movx 的每块一次 `vmv.x.s` 更贵（46,080 vs 40,960）；但打包后 B 连续，组合臂降到 22,528，说明连续装载 + 向量累加 + j 展开三者一起才划算。
- NEMU 的窗口退休指令数只作解释，不当周期：16³ 旧 vdot 8,074、movx 8,074（取回方式不改变指令总数）、vecacc 5,259、unroll4 5,533、vecacc_unroll 4,526；32³ 旧 vdot 49,385、movx 49,385、vecacc 31,051、unroll4 36,430、vecacc_unroll 28,043；见 `nemu_window_instr_explanatory.csv`。

## 64³ / 128³

**64³ 和 128³ 的真实周期仍是 `NOT_MEASURED`。** 本包没有用 NEMU 或微内核外推。

新变体在 16³/32³ 确实优于旧 vdot（6.55–10.55×），但 64³ 的老 vdot/打包臂按 32³ 的 `-C` 需求（100k/200k/400k）和 emu 吞吐评估会显著拉长作业，本轮没有拿到可靠的 **<24h** 吞吐证明，因此不提交 64³，保持 `NOT_MEASURED`；128³ 未跑。64³ 的本地 NEMU 功能 13/13 与窗口退休指令数（vector 344,586、旧 vdot 360,970、vecacc 274,893、unroll4 272,079、vecacc_unroll 197,388）只说明程序与校验可用，不是 64³ 周期，也不能写成加速比。

## 生成器与旧包的关系

`tools/gen_gemm_bench.py` 新增了 IMPL 3–6 的函数和 `kernel()` 分派；`gemm_scalar`/`pack_b`/`gemm_vector`/`gemm_vdot` 的函数体逐字节不变，64³ 旧臂的窗口退休指令数与 2026-10-19 包逐值相同（scalar 1,872,392、vector 344,586、旧 vdot 360,970、packed 389,966/406,350）。旧 `results/gemm/manifest.json` 里的 `tools/gen_gemm_bench.py` 输入哈希属于 2026-10-19 生成时；本轮没有改写那个 manifest、20 程序输出、旧 summary、旧日志或 `cycles_20261020/`。新包的 provenance 记录当前生成器哈希，旧 manifest 的哈希差异只来自新增的 IMPL 3–6 分支，不是旧内核被改。

## 限制

- 这是 **GEMM 内核+打包窗口**，不是完整程序启动+校验的端到端加速比；窗口外仍有启动、镜像加载、结果校验和 landing 自旋。
- 1024 周期网格；16³ 每臂 3 次，32³ 每臂 1 次；32³ 有 5 条 `-C` 不足的 FAIL 尝试（旧 vdot 2、旧 vdot_packed 2、旧集成 unroll4 1）保留。所有读数来自 `run_20261016_m` 的同一 emu/DiffTest，不外推到其他机器或频率。
- 没有改 RTL/ISA 的 vdot 语义，没有改旧基线实现、数据或窗口；旧 `cycles_20261020/` 原样保留。
- 不能把微内核的 3.667× 写成本包的任何加速比；本包的数字全部来自完整 GEMM 集成臂的 A/B。
- 64³/128³ 与完整程序端到端仍为 `NOT_MEASURED`。
