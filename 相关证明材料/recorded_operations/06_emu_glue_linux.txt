=== 1. 前置：先把顶换成 difftest 要的那个 ===
why: 本包此前生成的树顶是 XSTop，而 difftest/verilator.mk 用的是
     `--top-module $(EMU_TOP)`，EMU_TOP = SimTop，产出的是 VSimTop.h。
     树里没有 SimTop.sv，所以那个头文件根本无从产生——这是第一层。
how: 照上游 `make sim-verilog` 的 argv 重新生成一次
     （`mill ... xiangshan.test.runMain top.XiangShanSim`，带
     `--enable-difftest` 与 `--firtool-opt "--repl-seq-mem ..."`）
result: MILL_RC=0，产出 SimTop.sv（1222710 B）、XSTop.sv、filelist.f（2037 行）
top_ports_exposed: difftest_exit / difftest_step / perfCtrl / logCtrl / uart
                   —— 就是 DifftestEndpoint 那一组面

=== 2. 生成后必须补的两样（上游 Makefile 里本来就有，容易漏） ===

   `scripts/gen_sep_mem.sh` + `scripts/vlsi_mem_gen` 从 SimTop.sv.conf 生成。
   不跑它，Verilator 报 `Cannot find file containing module: 'array_15_ext'` 一族。
   本包在生成侧跑完，得到 26 个 `_ext.v`。
b) 外部模块 SimJTAG：把 extern_modules.sv 列的 59 个外部模块逐个与树内文件比对，
   **只有 SimJTAG 一个没有定义**（FlashHelper / SDCardHelper / Mem1R1WHelper 与
   全部 DiffExt* 都在树里）。它来自 difftest 的 `src/test/vsrc/common/SimJTAG.v`。
   filelist 由 2037 行补到 2064 行。

=== 5b. 整个 C++ 面（不只是那一支） ===
method: 照上游 Makefile 的变量取文件集，不是自己 glob。上游的编译集是
        VERILATOR_CXXFILES = EMU_CXXFILES + verilator/*.cpp
        EMU_CXXFILES       = SIM_CXXFILES + emu/*.cpp
        SIM_CXXFILES       = common/*.cpp + config/*.cpp
                             + build/generated-src/*.cpp + difftest/**/*.cpp
        于是 fpga/ vcs/ gsim/ plugin/xspdb/ 这些**别的后端各自的 main 不在其中**
        ——它们本来就该编不过（各自要自己的工具链与宏），扫进去只会得到噪声。
        第一版探针就是这么扫的，报出 28 个失败，其中多数属于这一类。
include_set: -I obj_dir
        -I $VERILATOR_ROOT/include -I $VERILATOR_ROOT/include/vltstd
        -I <difftest>/src/test/csrc/common -I <difftest>/config
        -I <difftest>/build/generated-src -I <difftest>/src/test/csrc/difftest
        -I <difftest>/src/test/csrc/emu -I <difftest>/src/test/csrc/verilator
        -I <difftest>/src/test/csrc/plugin/{spikedasm,runahead,simfrontend,topdown}
        （后三组的 -I 与 -I difftest 分别对应上游 Makefile:106 的
         `SIM_CXXFLAGS += -I$(DIFFTEST_CSRC_DIR)` 与 emu.mk:30 的 `-I$(EMU_CSRC_DIR)`）
defines: -DVERILATOR -DNUM_CORES=1 -DREF_PROXY=NemuProxy
        REF_PROXY 是上游按参考机类型生成的**类名**宏：Makefile:197-206 在
        `REF ?= Nemu` 且 $(REF) 不是一个存在的路径时给出 `-DREF_PROXY=$(REF)Proxy`，
        于是是 NemuProxy（声明在 refproxy.h:485）；difftest.cpp:490 那行是
        `proxy = new REF_PROXY(coreid, ram_size);`，宏缺了编译器就认不出类型名。
verdict: 47 支全过（ok=47 bad=0）。逐支读数由复跑脚本现算，本节不抄第二份。
meaning: difftest 的 C++ 面对这棵 Verilated SoC **编译干净**。

=== 6. 这一层是怎么一层层拆开的（四层，全是 include 路径） ===
VSimTop.h: No such file           <- emu_glue_probe.txt 记的原始卡点
  -> 生成带 SimTop 的树之后
verilated.h: No such file         <- 缺 Verilator 自己的 include 目录
  -> -I $VERILATOR_ROOT/include
config.h: No such file            <- 缺 difftest/config
  -> -I <difftest>/config
difftest-state.h: No such file    <- 缺 difftest 自己生成的头
  -> -I <difftest>/build/generated-src
rc=0
note: 这四层与 emu_glue_probe.txt 在 Windows 上撞到的那一族**不是同一类**。
      那一族是 LM_ID_NEWLM / RTLD_DEEPBIND / dlmopen —— glibc 独有的接口，
      非 glibc 宿主上缺的是接口本身。这四层缺的是路径，补上即可。
      所以「Windows 上过不去」不能读成「这一层过不去」。

=== 7. 这一份不主张什么 ===
not_a_link: 这是 `-fsyntax-only`，只编一个翻译单元，没有链接、没有生成可执行件
not_a_run: 没有参考机、没有程序、没有退休任何一条指令
not_a_link_2: 第 5b 节那 47 支是 `-fsyntax-only`。**没有链接**：没有生成
      `emu` 可执行件，没有编 `difftest-dpic.cpp` 的真实现，也没有接参考机的
      `.so`（缺 `REF`/`LINKED_REFPROXY_LIB` 那一组链接输入）
what_5b_does_not_cover: 第 5b 节用的是上游默认配置（未开 FPGA / VCS / gsim /
      DRAMsim3 / CHISELDB / 各 plugin 开关）。开了这些开关之后各自还要加
      `-D` 与 `-I`，本节不覆盖那些组合
nemu_unattached: 参考机库、ready-to-run 镜像、difftest 的运行时都没有接上；
      整层 3.1.2 仍是未做
single_host: 全部读数来自一台 Linux 宿主；换宿主能否复现不给结论
