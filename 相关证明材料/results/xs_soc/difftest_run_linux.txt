=== 3. 路上五处障碍（按出现顺序，全部是移植问题，没有一处是「做不到」） ===
a) include/config/auto.conf.cmd:8: multiple target patterns.  Stop.
   真因：Kconfig 的依赖文件在 Windows 上生成，末行是绝对路径 `D:/nemu-vdot/Kconfig`；
         make 把 `D:` 读成目标分隔符。它在 include 阶段就炸，连 defconfig 都跑不到。
   修法：把该绝对路径改写成相对的 `Kconfig`。

b) make[1]: <softfloat>/build/Linux-x86_64-GCC: No such file or directory
   真因：本包第一次打包 NEMU 树时用了 `tar --exclude=./build`，而 Windows 的 tar 把
         它解释成「排除任何名为 build 的目录」，把 `resource/softfloat/repo/build`
         一并排掉了。**这是本包打包方式的错，不是树的问题。**
   修法：重新打包，不加排除；那个目录里有 SoftFloat 的 Makefile 与 platform.h，
         目录本身必须存在。

c) make: No rule to make target chisel_db.cpp / fatal error: sqlite3.h
   —— 这两条属于 emu 那一侧，已记在 results/xs_soc/emu_build_linux.txt。

d) /bin/sh: <nemu>/tools/fixdep/build/fixdep: No such file or directory（Error 127）
   真因：config.mk:33 要 `tools/fixdep/build/fixdep`（无扩展名），而树里留下的是
         Windows 版 `fixdep.exe`；`tools/kconfig/build/` 同理（conf.exe / mconf.exe）。
         文件「在」但名字不对，make 认为不必重建，于是编译规则去调一个不存在的程序。
   修法：删掉这两个 build 目录，就地重编。

e) /usr/bin/ld: cannot find -lstdc++（"have you installed the static version..."）
   真因：scripts/build.mk:8 在 CONFIG_SHARE=y 时加 `-static-libstdc++`。与 `-shared`
         组合时 GCC 要的是**静态** libstdc++，本宿主不满足。
   修法：从该行去掉这个旗标。它只买到「运行期不依赖 libstdc++.so」，而本宿主有
         libstdc++.so.6。该文件本来就是为移植而改的：树里同时躺着 scripts/build.mk.orig，
         与 build.mk 只差 -Werror -> -Wno-error 一处。

另有一处影响运行的（不是构建）：见第 4 节。

=== 4. 24 字节的状态大小不一致，及其根因 ===
symptom: 参考机接上之后断言失败
         src/cpu/difftest/ref.c:427: difftest_init_v2: Assertion `false' failed.
         它前一句 printf 报的是
         ERROR: NEMU (1376B) is configured with different states than DUT (1400B).
         这句被 stdout 缓冲吃掉了，要用 `stdbuf -oL -eL` 才看得到。
why_it_is_24: NEMU 的 DIFFTEST_REG_SIZE 定义为
         offsetof(riscv64_CPU_state, difftest_state_end) - offsetof(..., gpr)。
         按 isa-def.h 逐项累加 gpr 512 + fpr 256 + 影子 CSR 152 + CONFIG_RVH 136
         + CONFIG_RVV 512 + CONFIG_DIFFTEST_CHECK_VCSR 56 + CONFIG_DIFFTEST_CHECK_FCSR 8
         = 1376，与 NEMU 自己报的 1376 逐字节吻合；余下的 24 正好是
         CONFIG_DIFFTEST_CHECK_SDTRIG 的 tselect / tdata1 / tinfo 三个 uint64。
root_cause: Kconfig 里 `config DIFFTEST_CHECK_SDTRIG` 有 `depends on RV_SDTRIG`，
         而这棵树的 defconfig 为了 Windows 构建把 `CONFIG_RV_SDTRIG` 关掉了 ——
         依赖不满足时 Kconfig **静默丢弃** 那条 `CONFIG_DIFFTEST_CHECK_SDTRIG=y`，
         不报错、不提示。于是 NEMU 的导出区比 DUT 少那 24 字节。
fix: 树里自带 configs/riscv64-xs-vdot_defconfig.bak-sdtrig，与 defconfig 逐行相同、
     只差 `CONFIG_RV_SDTRIG=y`。用它重建参考机，两侧都是 1400B。
lesson: **defconfig 里写着 `=y` 不等于它生效**；Kconfig 的 depends on 会让整行消失。

=== 5. 这一份不主张什么 ===
no_vdot_executed: 退休了 6 条指令，是复位后的启动序列；**没有执行任何 vdot.vv**，
         也没有跑完整启动（microbench 都没跑到）
not_the_competition_claim: 赛题要的是「跑一条含 vdot.vv 的程序并逐拍比对」。
         本文件只到「difftest 这一层建立了、能对撞」为止，**没有**跑那条程序
cycles_tiny: 2000 个周期。就 6 条指令而言这个数只说明启动刚开始
slow_by_choice: 2000 周期花了 25804 ms 主机时间（约 78 周期/秒），因为 emu 是以
         OPT_FAST="-O0" 链的。要跑真实负载必须换成 -O3（上游默认那档，注意
         `-fno-slp-vectorize` 是 LLVM 拼法，GCC 上要写成 -ftree-slp-vectorize 或省略）
         ——这是一条**性能**结论，不影响本文件关于「能不能跑」的结论
with_chiseldb_off: 这个 emu 是 WITH_CHISELDB=0 的裁剪配置，不是上游默认配置
         （理由见 results/xs_soc/emu_build_linux.txt 第 2 节 d）
single_host: 全部读数来自一台 Linux 宿主；换宿主能否复现不给结论
